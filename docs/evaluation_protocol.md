# Reachy Café 평가 프로토콜 (참가자 10명)

같은 10명이 한 번 앉은 자리에서 **라이브 A/B → 영상 설문 → 최종 질문**까지 마칩니다(1인 약 20분). 따로 사람을 더 모으지 않아도 두 논문과 연결된 결과까지 얻을 수 있게 짰습니다.

12/1 발표에는 토요일(11/28)까지 진행한 파일럿 4~6명의 결과를 "예비 결과"로 쓰고, 나머지는 12/8 전에 채워 보고서에 씁니다.

## 1. 무엇을 보여주려는가

| | 질문 | 비교 | 주 지표 |
|---|---|---|---|
| H1 | 로봇의 시선과 슬롯 LED가 결제를 쉽게 하는가 | A vs B | 결제 안내 → 카드 투입까지 걸린 시간, 투입 실수 |
| H2 | 실패에서 더 빨리 회복하는가 | A vs B | 품절·오인식 뒤 다음 주문 단계까지 걸린 시간, 재질문 수 |
| H3 | 경험이 나은가 | A vs B | UMUX-Lite, 맞춤 3문항, Godspeed 호감도 |
| H4 | Paper 1: forethought(Aha!)가 다음 행동을 읽기 쉽게 하는가 | 영상: expressive vs neutral | "다음에 뭘 할까" 정답률, 확신도 |
| H5 | Paper 2: 저자유도 감정 모션이 인식되는가 | 영상: expressive vs neutral | 감정 인식률, 정서가·각성 |

- **조건 A (Voice + Screen 키오스크)**: 같은 음성 대화, 같은 화면. 로봇 모션·시선·슬롯 LED·상태 스트립은 끕니다(오퍼레이터 패널 "조건 A").
- **조건 B (Reachy Café)**: 모두 켭니다.
- 전체 완료 시간은 B가 비슷하거나 조금 길 수 있습니다(감정 모션 시간). 숨기지 말고 탐색 지표로 보고하고, 이득은 실수·회복·경험에서 찾습니다.

## 2. 참가자

- 10명. 가능하면 외국인 학생 2명 이상을 넣어 영어 과제를 맡깁니다(목표 사용자 "외국인 방문객"에 가까움).
- 동의서: 녹화(얼굴 포함 영상은 데모·보고서용으로만), 로그는 텍스트·이벤트만 저장한다는 점을 설명합니다.
- 진행 인원: 오퍼레이터 1명(패널 조작·기록), 관찰자 1명(메모·시간), 안내자 1명.

## 3. 설계

- 피험자 내 2조건, 순서 상쇄: P01–P05는 A→B, P06–P10은 B→A.
- 조건마다 과제 2개. 같은 과제를 반복하지 않도록 난이도가 같은 쌍을 씁니다.

| 과제 | 첫 번째 조건 | 두 번째 조건 | 주입하는 실패 |
|---|---|---|---|
| T1 정해진 주문 | 아인슈페너 1잔 (품절) → 대안으로 주문, 카드 결제 | 캐러멜 마키아토 1잔 (품절) → 대안으로 주문, 카드 결제 | 품절 (재고 체크 해제) |
| T2 찾는 주문 | "카페인 없고 너무 달지 않은 음료"를 찾아 주문 | "따뜻하고 부드러운 음료"를 찾아 주문 | 없음 (추천 흐름) |

- 안내 문구는 하나로 고정합니다: "말로 주문해도 되고 화면을 눌러도 됩니다. 평소 키오스크를 쓰듯 해 주세요." 연습 시행은 없습니다(처음 쓰는 경험을 보려는 것).

## 4. 절차 (1인 약 20분)

1. 동의와 안내 (2분)
2. 첫 번째 조건: T1, T2 (각 2분 안팎) → 조건 설문 (2분)
3. 두 번째 조건: T1, T2 → 조건 설문
4. 영상 설문 (5분): 아래 6절
5. 최종 질문 (1분): "다시 쓴다면 어느 쪽? 이유는?"

**오퍼레이터 체크리스트 (시행마다)**
1. 패널 "평가 기록"에 참가자 ID·조건·과제 입력 → **기록 시작**
2. 조건 버튼(A 또는 B)을 누르고, 과제에 맞게 재고를 설정. 집계는 기록 칸이 아니라 **실제로 켠 기능**으로 조건을 정하므로 버튼을 꼭 누를 것 (둘이 다르면 `condition_mismatch`로 표시됨)
3. **세션 리셋** 후 참가자가 다가오게 함
4. 인식이 실패해서 패널로 개입했다면 관찰 메모에 적기 (로그에 operator 이벤트로 남고, 패널의 키오스크 미리보기 터치도 `assisted`로 자동 집계됨)
5. 패널 맨 위에 "🙋 직원 호출"이 뜨면 직원 역할로 참가자에게 가서 응대하고 "응대 완료"를 누르기 (규칙 밖의 질문이나 세 번 연속 못 알아들음. 응대 내용은 관찰 메모에, 호출 수와 이유는 `staff_calls`·`staff_reasons`로 자동 집계)
6. 모두 끝나면 `python tools/analyze_logs.py --only-trials`

## 5. 조건 설문 (각 조건 뒤, 7점 척도, 약 10문항)

| 척도 | 문항 |
|---|---|
| UMUX-Lite | 이 키오스크는 내가 원하는 것을 할 수 있게 해 주었다 / 이 키오스크는 사용하기 쉬웠다 |
| 맞춤 | 다음에 무엇을 해야 할지 알았다 / 키오스크가 내 말을 이해했다고 느꼈다 / 문제가 생겼을 때(품절 등) 당황스럽지 않았다 |
| Godspeed 호감도 | 싫다–좋다 / 불친절하다–친절하다 / 불쾌하다–유쾌하다 / 비호감이다–호감이다 / 끔찍하다–멋지다 (5점 의미 분별 척도 원형을 그대로 쓰거나 7점으로 통일) |

## 6. 영상 설문 (Paper 1·2 방식, 약 5분)

로봇만 나오는 짧은 클립을 순서를 섞어 보여줍니다. expressive와 neutral 변형은 HW4 YAML 그대로이므로 촬영만 하면 됩니다.

**H4 readability (Paper 1)**: Aha! 모션을 "present" 직전에서 멈춘 클립 2개(expressive, neutral) + 비교용 다른 상황 클립 2개
- "로봇이 다음에 무엇을 하려는 것 같나요?" (추천하기 / 주문 확인 / 인사 / 결제 안내 중 택1)
- 확신도 1–7

**H5 감정 인식 (Paper 2)**: 모션 4개 × 변형 2개 = 클립 8개
- 감정 선택: 기쁨·성공 / 실망·실패 / 지루함 / 깨달음·아이디어 / 모르겠음
- 정서가(불쾌–유쾌)·각성(차분–흥분) 1–9 (SAM)
- YAML의 `expected` 설계값과 비교합니다.

## 7. 분석 (n = 10)

- 기술통계(중앙값·사분위)와 참가자별 A→B 변화 그래프(선 10개)를 먼저 보여줍니다. 소표본에서 가장 설득력 있는 그림입니다.
- 대응 비교는 Wilcoxon signed-rank, 효과크기 r = Z/√n. p값보다 방향과 효과크기로 해석합니다.
- 영상 설문: 변형별 정답률(참가자별 정답 비율의 Wilcoxon), 감정 혼동행렬.
- 로그 지표는 `tools/analyze_logs.py`가 세션별 CSV로 뽑습니다: 완료 여부, 완료 시간, 카드 투입 시간(H1), 결제 전 카드 투입 수(`wrong_step_cards`), 품절 회복 시간(`sold_out_recovery_s`, H2)·되묻기 회복 시간(`repair_recovery_s`, H2), 재질문 수, 도움 제안 수, 추천·거절 수, 오퍼레이터 개입 수(`assisted`), 직원 호출 수와 이유(`staff_calls`·`staff_reasons`, 조건별 `staff_sessions`), 음성 인식 지연(`median_asr_s`), 로봇이 말을 시작하기까지(`median_reply_s`).
- `median_reply_s`에는 조건 B의 의도한 대기(시선이 먼저 가는 0.3 s, 인사 0.4 s, Aha!의 present 1.7 s)가 들어가므로 A/B 반응 속도 비교에 쓰지 않습니다. `assisted`가 0보다 큰 시행은 따로 나눠 봅니다 (8절).

- 같은 사람이 두 조건을 모두 써서 학습 효과가 있습니다(순서 상쇄로 완화).
- 오퍼레이터가 인식 실패를 보완한 시행이 있으면 따로 표시하고 결과를 나눠 봅니다.
